## Decisiones de «dejar como está» (deliberadas)

- **5 error boundaries** (`Root/Network/SignalProcessing/Camera/VitalSigns`): cada uno tiene estado y UI propios (retry con backoff, modo degradado, reload). Se evaluó una clase base común; el ahorro (~10 líneas por clase) no compensa el riesgo/la complejidad genérica. Documentado aquí.
- **Literales de UI de señal** (`isOpenFlashWithoutContact`, `isExposureFlickerNotFingerPulse`) en presentación: heurísticas de etiquetado de estado con condiciones de una sola pantalla; moverlas a config crearía claves de un solo uso.
- **`.npmrc` con `legacy-peer-deps=true`**: se mantiene (árbol con @capgo/capacitor-health); tras la subida a react-hooks 5.2.0 la instalación limpia pasa igualmente.
- **`lovable-tagger`** (dev) y **gateway `LOVABLE_API_KEY`** del edge: forman parte del hosting actual. Para desacoplarse de Lovable hay que sustituir el proveedor de IA del edge y quitar el tagger; no se hizo por no romper el deploy actual.
- **`isFallbackMode` / worker**: el fallback main-thread es real (mismo procesador), no simulación.
